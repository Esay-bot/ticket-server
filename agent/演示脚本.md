# 3 分钟演示脚本（票务智能预订 Agent）

> 录屏建议：左边 WSL 终端跑服务端 + tail 日志，右边 Windows 终端跑 Agent CLI。
> 准备：`wsl` 里 `sudo service mysql start && cd ~/ser-cli/server && ./ser`；Windows 侧已 `export DEEPSEEK_API_KEY=...`。

## 0:00–0:20 开场（讲稿）

"这是我自己写的 C++ libevent 高并发票务服务，单线程 IO + 4 线程业务池 + MySQL 连接池，跑在 WSL2 里。
现在给它套一个智能 Agent：用户说人话，Agent 通过**自研二进制协议**直接调这个服务，
不改服务端一行代码。协议是 4 字节大端长度头加 JSON。"

（可展示 `agent/protocol.py` 的 `try_extract_frame` 10 秒：粘包半包处理。）

## 0:20–0:50 登录 + 查票

```
python -m agent.main
# 选 1 登录: 13900000001 / 123456

你: 10月份有什么票?
```

预期：助手调用 `query_tickets` 工具，逐条列出 4 个班次的编号、线路、日期、余票。
（讲："模型决定调哪个工具，工具走我的 TCP 客户端。注意成都只剩 1 张、广州售罄——这是评测埋的场景。"）

## 0:50–1:40 亮点一：确认门控（先拒绝，再放行）

```
你: 帮我订10月1日去北京的票
```

预期：助手**先复述**「西安-北京 2026-10-01，余票 100 张，确认预订吗？」——此时不下单。

（讲："预订有真实副作用，所以闸门在代码执行层：模型没拿到用户确认，就根本发不出 type=4 的包。"）

```
你: 确认
```

预期：助手调用 `reserve_ticket(confirmed=true)`，回复预订成功。
（讲："确认后模型带上 confirmed 标记重调同一工具，这才真正发包。"）

## 1:40–2:20 亮点二：售罄主动推荐替代

```
你: 订10月4日去广州的
```

预期：工具返回 `sold_out` + 有余票班次列表，助手自然语言解释售罄并**主动推荐替代班次**。

```
你: 那订10月2日去上海的
确认
```

预期：改订成功。

## 2:20–2:45 闭环：查我的预约 → 取消

```
你: 我名下有哪些预约?
你: 取消西安-北京那条
确认
```

预期：列出预约 → 复述预约号与班次 → 确认后取消成功。

## 2:45–3:00 收尾：评测数据

```
python -m agent.evaluate            # 或直接展示已有 eval_results/*.json
```

（讲："26 项任务、7 大类的评测集：成功率、平均轮数、token 用量，与命令行操作步数对照。
成功判定不靠模型自述——结束后直连服务核对预约状态。"）

## 常见追问的现场演示备选

- "模型不听话直接订怎么办？" → 展示 `test_agent.py` 的 B 用例：同轮自问自答被拒，`type:4` 帧从未出现。
- "并发下会不会乱？" → `protocol.py` 请求锁 + 服务端事务扣票。
- "换模型要改多少？" → 只改 base_url / api_key / model 三处。
